# 参与贡献

感谢你愿意帮助预见变得更好。无论是否会写代码，都可以参与。

## 不会写代码也能贡献

### 报告 Bug

请使用 Bug 模板，并尽量提供：

1. 你执行了哪些操作。
2. 你原本期待看到什么。
3. 实际发生了什么。
4. 是否每次都能复现。
5. macOS 版本、芯片型号和应用版本。
6. 截图或不超过一分钟的录屏。

公开上传项目文件前，请删除剧本、客户名称、未发布素材和其他敏感信息。

### 提出功能建议

请先描述你的真实创作场景，再描述想要的按钮或交互。一个好的建议通常包括：

- 谁在什么情况下会用它。
- 现有流程哪一步最费时间或容易出错。
- 你希望完成任务后得到什么结果。

## 代码贡献流程

1. Fork 仓库并创建一个只处理当前任务的分支。
2. 安装 Node.js 22。
3. 执行 `npm ci` 安装依赖。
4. 从 `docs/TASK_TEMPLATE.md` 建立任务验收单。
5. 执行 `npm run test:impact -- --base main`，确认修改前的相关测试通过。
6. 完成修改并补充必要测试。
7. 再次执行影响测试；提交 Pull Request 前执行 `npm run test:full`。
8. 提交 Pull Request，引用验收单并说明动机、改动、验证证据和剩余风险。

请把一个 Pull Request 聚焦在一个问题上。较大的功能建议先开 Issue 讨论，避免双方重复投入。

`npm test` 只运行快速核心启动冒烟；它不能代替提交前的 `npm run test:full`。详细规则见 `docs/DEVELOPMENT_WORKFLOW.md` 和 `docs/TEST_STRATEGY.md`。

## 代码和界面原则

- 优先保持导演工作流直观，避免为了参数完整而堆叠控制项。
- 不破坏现有项目文件兼容性；如果必须变更数据结构，需要提供迁移逻辑。
- 涉及路径、时间轴、摄影机和导出流程的改动必须补充回归测试。
- 新增或修改界面文案不得直接写进 HTML、JavaScript 或 Electron 逻辑。请在 `i18n/locales/zh-CN.js` 与 `i18n/locales/en-US.js` 同时增加 language key，并在代码中使用 `PreVisionI18n.t()`、`data-i18n*` 或 Node 端 `t()`。
- 提交前必须运行 `npm run test:i18n`；语言包 key 不一致、引用缺失或运行时代码新增直接中文都会失败。
