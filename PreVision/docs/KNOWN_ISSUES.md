# 已知问题与限制

更新时间：2026-07-29

## 发布阻塞

### KI-001 许可证尚未确定

公开 GitHub 仓库前必须由项目所有者选择许可证。AGPL、非商业源码可见许可和 MIT 的权利边界不同，不能由开发代理代替决定。

### KI-002 GitHub 尚未连接

本地没有 remote/origin，GitHub CLI 未登录。当前可以完整执行本地分支和提交流程，但不能创建 PR、远程 Actions 或 Release。

### KI-003 macOS 未正式签名和公证

现有构建使用 ad-hoc 签名，只适合本机和开发验证。分发给普通用户前需要 Apple Developer ID、Hardened Runtime、权限文件和 notarization。

## 开发环境

### KI-004 系统默认 Node 版本过高

本机默认 Node 26.3.0 超出项目允许的 20–24。测试目前可运行，但 Electron Forge 曾在 Node 26 下最终封装阶段静默退出。统一使用 `.nvmrc` 的 Node 22。

### KI-005 没有 lint 和 typecheck

当前只有运行时/结构测试和 Node 语法检查。原生 JavaScript 缺少静态类型边界，复杂数据迁移和 IPC 输入更依赖测试与评审。

### KI-014 本机 Git 身份尚未配置

仓库和全局配置中没有用户姓名与邮箱。阶段检查点和本次基础建设使用明确的临时本地提交身份，后续连接个人 GitHub 前应由项目所有者设置真实的仓库级身份；开发代理不能猜测邮箱。

## 架构与测试

### KI-006 主应用为单文件架构

`预见PreVision.html` 同时包含压缩 Three.js、CSS、DOM 和几乎全部业务逻辑。Git 文件级影响分析无法自行区分摄影机、时间轴或场景模块；验收单能证明单模块归属时可显式运行登记模块测试，否则仍需运行完整应用测试。真正的函数/文件级隔离要等后续架构拆分。

### KI-007 媒体流程缺少真实端到端自动化

日常录屏和视频导出回归仍以 MediaRecorder、Canvas 和浏览器 API 桩为主。2026-07-15 新增的 Web 压力工装已在真实 macOS Chrome 走通 2 秒录屏和 Seedance 打包；2026-07-17 的 01.14 任务又在真 macOS Chrome 与隔离 Electron 覆盖当前镜头、本场景、Seedance 的身份隔离、悬挂纹理预检的真实停止按钮、MediaRecorder 无 `onstop` 的单次兜底、取消恢复与手动工作区录制入口，但这些仍是单机短时验证。Safari 和 Windows Chrome/Edge 尚未补齐，也没有建立长时间录制阈值；编码器差异、长录制内存、帧率稳定和系统权限仍必须在发布前按平台真机检查。

### KI-020 Web 反复切换场景时三维资源持续增长（源码已集成，固定 App 待更新）

当前源码已通过 `d4bb4be`、`f0f0572`、`62e20fe` 集成 04.5：scene actor/label/viz/sky 等独占资源具有可重入 dispose 边界，项目级 `assetTex` 覆盖成功提交、失败回滚、新建项目和 orphan GC 的 owner 生命周期。2026-07-16 同一物理机、同一 Chrome standard 矩阵中，基线 40 次切换 geometry `565→17,244`、texture `28→988`，修复后为 geometry `452→451`、texture `27→27`；随后 120 秒为 geometry `451→448`、texture `27→27`，短播放 60 FPS/p95 17.7ms，零 console error/context lost/crash。证据位于 `docs/qa/three-resource-lifecycle/`。固定 App 仍为 `7ff9aa5`，尚未包含该修复；Safari/Windows 真机矩阵也仍未补齐，因此不得把“源码已集成”写成“固定 App 已安装”或“跨平台问题已完全关闭”。

### KI-021 极端 texture dispose 抛错后该对象不可重试

`disposeAssetTextureCache` 会在单个 texture 的 `dispose()` 抛错时删除 cache owner、记录错误并继续释放后续项，避免一个异常阻断整个项目回收。由于幂等保护会先标记该资源，异常对象本身不会再次尝试 dispose；执行级测试已钉住“后续项继续清理”，这个只在底层 Three.js/custom texture dispose 非正常抛错时出现的残余按 P3 保留。若未来引入可抛错的自定义 GPU 资源，再单独设计可观测的重试/隔离机制，不在本任务扩张架构。

### KI-008 Electron sandbox 关闭

`contextIsolation` 已开启且 `nodeIntegration` 已关闭，但 `sandbox:false`。当前 preload 很小；新增 IPC 时仍需严格输入验证，并应单独评估未来启用 sandbox。

### KI-009 自动保存受 localStorage 容量限制

应用在图片资产导致配额溢出时会降级为不含图片的保存，但大项目仍可能需要更可靠的桌面文件存储和恢复机制。

### KI-015 历史界面中文尚未全部迁移

language key 基础设施和新增中文守卫已经建立，但单体主应用中仍有大量规范生效前的内联中文。它们属于遗留基线，不代表已经支持完整语言切换；后续按功能模块触碰即迁移，避免一次性大改造成行为回归。

### KI-016 独立 package 仍会生成可见 App

日常唯一入口已经固定为 `~/Applications/PreVision.app`。`app:update` 在成功安装后会清理它刚生成的源 App，避免 Finder/Spotlight 再出现第二入口；2026-07-14 已将原桌面仓库的旧构建与备份移入废纸篓。但单独运行 `npm run package`、其他工作树打包或从废纸篓恢复旧包，仍可能生成额外 App；这些分发/诊断产物不应固定到 Dock 或作为日常入口。

### KI-017 并行任务仍需明确整合

本地交付门禁会阻止兄弟或落后分支覆盖固定 App，但不会猜测如何自动合并两个同时修改业务代码的分支。后完成的并行任务如果不包含当前 installed source，必须先解决冲突并整合最新已交付提交，再运行 `app:deliver`；门禁失败不代表任务已完成。

## 产品边界

### KI-010 碰撞不是专业物理仿真

当前使用包围盒和离散移动保护，适合预演接触关系，但无法保证快速连续运动、复杂网格、人体关节或布料的真实碰撞。方形沙漠使用专用确定性高度场让对象和骑乘组合保持在表面上方，但人物脚掌和马匹四蹄不会针对坡面单独做 IK 变形。

### KI-011 背景与全景需要人工视觉校准

代码支持全景和图板，但透视、地平线、尺度和真实素材质量无法只靠自动测试判断。

### KI-012 平台覆盖有限

桌面构建仍只验证 macOS arm64。静态 Web 已在真实 macOS Chrome 完成一轮标准压力矩阵，但 Safari 因 Remote Automation 未授权而阻塞，Windows Chrome/Edge 因没有真实 Windows 环境而未运行。Intel Mac、公开 Web 部署和 ComfyUI 仍未实现或未验证；不得用 CI 或 macOS 浏览器冒充 Windows 证据。

### KI-022 固定 LAN 预览不是加密协作或公网分享

固定 LAN 最新预览使用明文 HTTP，只适合受信任的同一物理私有 IPv4 子网。服务按默认 `en*` 接口精确绑定、Host allowlist、同子网远端源和网络变化 fail-closed 限制暴露面，但不提供 TLS、账号、授权令牌、设备同步、审计或公网防护。每台设备的 localStorage 和项目文件完全独立；第二真实 LAN 设备、不同路由器和网络切换仍需持续补充实机证据。需要远程分享、互联网访问或多人协作时必须另立带认证/TLS/不可信项目隔离的业务服务，不能放宽本机 LAN runtime。

### KI-018 离线分镜规划是受限的确定性启发式

当前规划器只面向单个场景和最多两名主要角色。它能解析常见中英文对白、动作、环境与剧本标点，审计节拍覆盖，并提供基础轴线、视线、主体入画和数值保护；但不做多场次批处理、三人以上复杂对白、语义模型推理、复杂遮挡搜索、姿态/动作路径自动生成或电影级镜头优化。歧义文本会以较低置信度和明确警告回退，仍需用户在临时预览中检查后再应用。

### KI-019 语义代理只能验证 PreVision 内部参考一致性

语义代理模型库提供粗糙、可读、低复杂度的场景参考物，不是高精 3D 资产库。自动测试只能验证代理 ID、尺寸、保存恢复、碰撞语义和本地参考一致性；Seedance 或其他外部视频模型是否在多镜头中保持真实场景一致，必须由用户用导出参考帧和语义清单进行实机评估。

## 私有本机资料

### KI-013 忽略目录含旧历史材料和本机路径

`日志/`、`CLAUDE.md`、`.claude/` 可能含旧产品名称、实验记录和本机路径。它们已经被 `.gitignore` 排除，不得直接加入公开提交；可用信息应先去敏并迁移到正式文档。
