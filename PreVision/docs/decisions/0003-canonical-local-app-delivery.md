# ADR-0003：用户可见任务必须交付到唯一固定 Mac App

状态：Accepted
日期：2026-07-14

## 背景

PreVision 使用多个 Codex 工作树并行开发。Bug、新功能和 UI 任务分别在兄弟分支完成后，代码与测试虽然存在，但用户日常打开的 `~/Applications/PreVision.app` 只包含最后一次执行安装的分支。兄弟分支不会自动互相包含，旧分支还可能在稍后安装时覆盖已经交付的新功能。

## 决定

1. 本机唯一用户入口是 `~/Applications/PreVision.app`。
2. 每个用户可见任务开始前运行 `npm run app:status`，确认任务基线包含固定 App 的 installed source。
3. 并行任务完成较晚时，必须先安全整合最新交付提交；不允许用兄弟或落后分支直接更新固定 App。
4. Forge 在 App 包内写入 `prevision-build.json`，记录干净提交的 commit、branch、构建时间与可交付状态。
5. 更新器读取当前固定 App 的来源，使用 Git 祖先关系阻止功能回退，并验证新包来源与当前 HEAD 完全一致。
6. Bug、新功能、UI/交互和其他用户可见任务必须执行 `npm run app:deliver`。该命令依次完成全量测试、安全更新和自动启动；任一步失败，任务不得标记完成。
7. 纯文档、纯测试和不改变安装包的仓库任务可以不安装，但必须在验收单说明。
8. 一条用户消息不等于一个完整任务。任务内多轮调整使用开发预览和相关模块测试；只有进入“可以了、定稿、正式更新”等最终验收阶段时执行一次正式交付。有歧义时默认预览，不擅自打包。

## 后果

- “代码完成”和“用户可见”不再是两个独立状态。
- 并行分支不能静默覆盖彼此；发生分叉时会在构建前失败并要求整合。
- 每个安装包能追溯到具体 Git commit 和 branch。
- 本地交付仍不等同于正式签名、公证或对外 Release。

## 验证

- `npm run test:local-install`
- `npm run test:full`
- `npm run app:deliver`
- `npm run app:status`
- 从固定路径启动并人工确认本次变化。

## 撤销条件

未来若建立正式 CI/CD、自动更新器或签名发布通道，可用新 ADR 替换本机安装实现；“用户可见任务必须产生可追溯可运行交付物、并且不能回退已交付功能”的原则继续保留。
