## 用户问题

大幅优化软件界面、图标、各级菜单、边栏展开方式和各栏尺寸，参考 Blender、Unreal Editor 5 等专业创作软件；先提供多个风格版本，并覆盖白天、夜晚及其他软件界面主题。

## 目标

- 基于当前真实界面输出四套可比较的高保真视觉方向稿，而不是直接改动生产界面。
- 给出统一的工作区布局、图标、菜单、面板层级、尺寸和展开/收起交互原则。
- 规划至少日间、夜间和一种特色主题，并确保主题只改变视觉令牌，不改变摄影机、时间轴、路径或项目数据逻辑。
- 为用户选型后的实现阶段提供明确、可测试的设计基线。

## 非目标

- 本阶段不修改 `预见PreVision.html`、Electron 逻辑或项目数据格式。
- 本阶段不实现完整主题切换、面板拖拽、图标系统或响应式布局。
- 不照搬 Blender、Unreal Editor 的品牌资产、商标、专有图标或像素级界面。
- 不调整摄影机、时间轴、路径、播放、保存或项目迁移语义。

## 证据与现状

- 代码：主界面、样式和业务逻辑集中在 `预见PreVision.html`，布局模块登记为 `layout`。
- Git：从 `chore/prevision-development-foundation` 的 `02cf401` 创建独立分支。
- 测试/运行：基础分支记录 `layout` 模块 24 项通过；约 1316×768 窗口已有轨道展开、紧凑拖拽和隐藏人工检查证据。
- 文档/历史线索：`ARCHITECTURE.md` 要求普通功能任务不拆分整个单文件应用；`TEST_STRATEGY.md` 要求 UI 布局记录目标窗口尺寸和明确人工步骤。

## 风险

- 数据：本阶段无运行时数据变更；实现阶段必须保持项目数据 v5 兼容。
- UI/交互：概念稿可能低估单文件实现成本；必须把视觉方向与交互机制分开评审。
- 安全：不引入外部在线资源、真实服务调用或用户私人项目素材。
- 发布：本阶段不生成应用构建；图标与字体落地前需确认许可和离线打包方式。

## 测试计划

- 影响映射模块：foundation；若后续修改主应用则升级到 layout + foundation，跨模块时升级到 app/full。
- 主应用模块参数：本阶段无；实现阶段使用 layout。
- 最小命令：`npm run test:foundation`。
- 升级到全量的条件：修改 `预见PreVision.html`、测试夹具、数据格式，或面板交互触及摄影机/时间轴/路径状态。
- 人工检查尺寸/步骤：以 1440×900 为主稿，额外核对 1316×768（当前 MacBook 证据尺寸）、1728×1117；依次检查菜单关闭/打开、左栏展开/折叠、右栏展开/折叠、时间轴展开/紧凑/隐藏、日间/夜间/特色主题切换前后信息层级与画布可用面积。

## 实施记录

- 假设：首轮先对齐视觉和交互方向，用户确认后再创建实现任务；主视口始终是最高优先级区域。
- 关键决定：四套方案共享同一功能信息架构，以便比较风格而非比较不同产品；借鉴专业 DCC 工具的密度、可停靠面板和状态表达，但不复制其品牌资产。
- 实际修改：新增离线 HTML/CSS 设计稿、四套布局截图、三套同结构主题截图、B 方案 1316×768 与 1728×1117 尺寸截图，以及完整设计/实现边界说明；生产 HTML、Electron 和数据格式未修改。
