- 状态：completed
- 日期：2026-07-14

## 用户问题

四个专用对话完成 Bug、新功能或 UI 优化后，用户从桌面入口重新打开 Mac App 看不到变化。要求以后每完成一次优化，都必须重新更新日常使用的程序，并能在重新打开后看到对应变化。

## 目标

- 确认固定安装入口与各任务分支之间脱节的真实原因。
- 建立唯一的本地可交付基线，禁止任意旧分支直接覆盖最新安装包。
- 把“构建、更新固定 App、核对来源、启动验收”加入所有业务任务的完成定义。
- 将当前所有已完成且未进入安装包的 UI 提交整合进可交付基线。
- 更新 `~/Applications/PreVision.app`，并验证固定入口确实来自本次可交付提交。
- 将同一规则同步到 Bug、新功能、UI 和工程发布四个专用对话。

## 非目标

- 不自动合并到 `main`，不强推或覆盖远程分支。
- 不替代正式 Apple Developer ID 签名、公证和对外发布流程。
- 不把未完成、测试失败或存在冲突的任务强行装进固定 App。
- 不删除用户项目、自动保存、导出文件或历史 Git 分支。

## 证据与现状

- 代码：仓库已有安全更新脚本 `scripts/update-local-app.mjs`，但任务分支缺少统一集成来源与完成门槛。
- Git：固定 App 对应 `fix/single-visible-prevision-app`；最新 UI 提交 `25be3a4` 位于兄弟分支，未包含在安装包中。
- 测试/运行：安装包内主 HTML 哈希与 Bug 分支一致，与 UI 分支和当前根工作树均不一致。
- 文档/历史线索：现有流程要求需要时运行 `app:update`，没有要求每个可见业务任务完成前必须从统一基线安装并验证。

## 影响范围

- 模块：本地安装、Git 交付流程、应用来源追踪、完成定义。
- 文件：安装脚本与测试、package scripts、AGENTS、流程/发布/测试文档、任务模板、QA 映射。
- 数据格式：无。
- 平台：macOS Apple Silicon 本地开发安装。

## 风险

- 数据：安装包替换不得触碰用户项目与 Application Support。
- UI/交互：固定 App 如果从错误分支构建，可能看不到新功能或丢失另一分支已完成能力。
- 安全：安装必须保持 bundle ID、签名、路径、锁和回滚校验。
- 发布：系统默认 Node 26 不允许打包，必须使用项目提供的 Node 20–24 运行环境。

- 影响映射模块：local-install、desktop、main-app、foundation、i18n。
- 主应用模块参数：无，最终运行全量应用测试。

## 实施记录

- 假设：固定日常入口继续使用 `~/Applications/PreVision.app`。
- 关键决定：任务分支不能各自争抢固定 App；只有安全合入统一可交付基线后才能更新安装包。
- 实际修改：整合遗漏的品牌副标题 UI 提交；为 Forge 包写入 Git 来源；新增固定 App 来源状态、分支祖先和打包期间源码稳定性校验；新增 `app:deliver` 串联全量测试、安全更新和自动启动；把该步骤写入代理入口、任务模板、评审、测试、发布、架构和 QA 登记。
