## 用户问题

打开安装在本机的 App 或此前使用的网页入口时，看到的仍是旧版本界面。

## 目标

- 确认已安装 App、常用网页入口与当前 UI 提交之间的版本差异。
- 使用允许的 Node 20–24 环境重新打包当前 B 主界面、C 专注模式与四主题版本，并安全更新本机入口。
- 建立明确、稳定的本地网页预览入口，避免继续打开桌面仓库中的旧 HTML。
- 验证 App 与网页入口都加载当前提交，同时不改变项目数据和摄影机、时间轴、路径语义。

## 非目标

- 不建立公开网络部署、GitHub Pages 或公开源码仓库。
- 不修改 UI 视觉设计、项目数据格式或 Electron IPC 语义。
- 不建立正式 Apple Developer ID 签名或公证。

- 代码：当前工作树 `预见PreVision.html` 包含 `setUITheme`、四主题与 `setDirectorFocus`；桌面仓库副本不包含这些入口。

- 数据：替换应用包不得删除 Electron userData 或用户项目文件。
- UI/交互：安装前为旧界面；安装后应出现 B 电影控制台、四主题和 C 导演专注，栏位偏好与专注临时状态保持既有语义。
- 安全：不公开源码，不调用真实付费服务；本机包仍仅为 ad-hoc 签名。
- 发布：错误替换路径可能留下两个同名 App；必须记录并校验实际启动路径与包内 HTML 哈希。

- 假设：用户期望更新本机可打开的预览，不授权公开发布。
- 关键决定：保留用户数据目录；仅替换应用包或新增稳定入口，不改项目 v5。
- 根因：实际启动的是桌面旧工作树 `02cf401` 的开发包，包内 HTML SHA-256 为 `1622fe9d905418e0d614380d1d250532d2440c721579eeed5b7b2209b7dbdcb1`；当前 UI 提交 `2570518` 的 HTML SHA-256 为 `9652d40e727644f5c807e94da616217e9bef6951569f21d7250f3ef1b6e1d01c`。页面未注册 Service Worker，项目也没有公开 Web 部署，因此不是缓存问题。
- 实际修改：使用 Node 24.14.0 和 lockfile 安装依赖并重新 package 当前 macOS arm64 `.app`；包内 HTML、源码与安装副本哈希一致。
- 实际修改：在用户 Applications 目录安装稳定 `PreVision.app`，同时刷新原常用开发包点击路径；旧包保留为带原提交标识的备份。
- 实际修改：复制当前 HTML、品牌图标与 `html2canvas` 本地依赖为独立网页入口，并启动仅绑定 `127.0.0.1` 的回环静态预览；没有创建公开托管、域名或源码发布。
- 实际修改：新增本任务 QA 说明与截图，更新当前状态及桌面/本地 Web 功能证据；未修改生产 HTML、Electron 代码或数据结构。
- 数据保护：安装没有删除、替换或迁移 Electron 用户数据目录；启动验证产生了正常的 Electron/Chromium 状态写入，但用户 Documents 下项目/导出区的安装后 mtime 变化数为 0，且没有读取或改写私人项目内容。
