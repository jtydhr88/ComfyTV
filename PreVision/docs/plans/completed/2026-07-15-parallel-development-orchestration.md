## 用户问题

重组当前项目的总协调、Bug、新功能、UI 和工程任务体系；避免长对话拖慢响应；任何并行任务在写代码前必须识别与其他正在进行工作的逻辑、功能、数据和界面冲突，并先向用户说明风险。

## 目标

- 建立新的当前周期总协调任务，历史开发归档退为只读参考。
- 统一四个核心任务的名称、职责和按需子任务规则。
- 用所有 Git worktree 共享的本机任务声明，检测模块、UI 表面、数据区域和文件重叠。
- 将硬冲突阻止在写代码之前；软冲突必须提前报告合并顺序和风险。
- 保持“一项具体结果、一份短上下文、一个 Worktree、一个分支、一个验收单”。
- 限制并行写任务数量，避免单文件架构造成合并拥堵。

## 非目标

- 不创建十三个空闲且长期积累上下文的开发任务。
- 不修改 PreVision 业务功能或固定 App。
- 不公开仓库、不连接 GitHub、不调整生产数据。

## 证据与现状

- 当前固定 App 与本分支基线均为 0.7.1 `de0c6ac`。
- 四个专用任务仍保存早期工作树和旧基线；不得直接用其旧分支覆盖固定 App。
- 主应用业务集中在 `预见PreVision.html`，仅按文件名判断会把所有业务任务误判成同一冲突，因此需要模块、UI 表面和数据区域的细粒度声明。
- 官方 Codex 工作方式支持项目任务、Worktree 和子代理；长期事实已进入 `AGENTS.md` 与 `docs/`，无需复制历史长对话。

## 影响范围

- 模块：repository、workflow、testing、i18n policy、local delivery policy。
- 文件：`AGENTS.md`、开发流程/测试/评审文档、任务模板、`package.json`、并行声明脚本及测试、QA 元数据。
- 数据格式：不修改项目数据 v5；任务声明只写入 Git common dir，不进入提交。
- 平台：本机 Codex 桌面项目与所有 Git worktree。

## 风险

- 声明过粗会制造假冲突；声明过细会漏掉共享状态入口。
- 多个任务同时更新声明文件必须有原子锁与安全清理。
- 空闲任务过多会增加上下文、磁盘和工作树维护成本。
