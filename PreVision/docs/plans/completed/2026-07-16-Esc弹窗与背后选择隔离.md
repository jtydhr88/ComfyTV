## 用户问题

普通/分镜弹窗打开时按 Esc，全局快捷键会先清掉背后选择，随后浏览器默认 cancel 才关闭弹窗。

## 目标

- 任一 open dialog 接收 Escape 时隔离全局场景快捷键，同时保留浏览器原生 cancel/default action。
- 保留分镜弹窗应用内全屏的两阶段 Esc 语义；普通态 Esc 只关闭最上层弹窗并保留背后选择、高亮与 inspector。
- 覆盖 keys、template、confirm、story dialog，以及两层 modal 的 topmost 行为和零项目副作用。

## 非目标

- 不改菜单、整体键盘体系、弹窗视觉、项目 history 或 autosave 语义。
- 不新增用户文案或 language key，不改 story dialog 既有 cancel 语义。
- 不运行 `app:deliver`，不更新固定 App，不使用端口 4175。

## 实施记录

- 假设：浏览器在 keydown 未被 `preventDefault()` 时继续为 topmost modal 触发原生 `cancel`/关闭默认动作。
- 关键决定：只在统一 `hasOpenDialog()` 守卫中调用 `stopPropagation()` 并立即返回；不 `preventDefault()`、不手动 close，分镜既有 cancel 处理保持不变。
- 实际修改：全局 Escape 路由增加四类 open dialog 守卫；DOM 工装增加真实 keydown→cancel→default close 链，覆盖普通、确认、层叠与分镜全屏两阶段及零副作用。
