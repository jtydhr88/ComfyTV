## 用户问题

录制与自动视频导出共享全局 MediaRecorder、tick、track、stop 引用，多个入口可并发覆盖当前会话。自动导出期间顶栏显示停止状态，但停止回调并未连接；部分导出入口用空 catch 吞掉失败，表现为点击无反应。

## 目标

- 为工作区录制、摄影机手动录制、自动当前镜头/场景视频导出和 Seedance 视频生成建立单一捕获事务所有权与程序性 fail-safe。
- 手动录制维持停止并保存；自动导出停止必须真实取消、不保存部分视频，并恢复既有预览/选择/播放状态。
- 所有完成、取消、错误、轨道结束、异常和重复停止路径只结算一次，彻底清理录制定时器、轨道、事件处理器和事务锁，随后可立即重启。
- 所有忙碌、失败、取消反馈通过双语 language key 呈现，不再静默吞错。

## 非目标

- 不重排截图、录屏或导出菜单，不移动控件。
- 不做安全镜头、首尾帧 ZIP 或其他大媒体工作流。
- 不改变截图、编码格式、Electron 保存位置、导出内容或 project/autosave/history 语义。
- 不运行 `app:deliver`，不更新固定 App，不部署，不占用端口 4175。

## 实施记录

- 假设：单一事务只约束占用录制/编码器和全局预览恢复状态的入口；截图不占事务。
- 关键决定：事务 token 从入口（含保存目标等待和 Seedance 预渲染）持续到调用方最终结算；底层只清理自身 MediaRecorder，Seedance 外层锁保持到 ZIP 下载 finally。自动恢复使用 label/索引快照，不保留跨 scene 的旧 Object3D 引用。
- 实际修改：新增捕获事务所有权、真实 stop、exactly-once 清理、轨道 ended/error 处理、自动状态快照恢复和双语反馈；移除 shot/scene 导出的空 catch；Seedance 预渲染和打包全程可取消且保持互斥。
- 第三轮终审补丁：legacy `captureStream` 无 `requestFrame` 时仅保留实际 track 用于 ended/cleanup，初始化期任一 `getVideoTracks`/`getTracks`/stop 失败均停掉已创建 stream 并释放所有权；摄影机手动 6h hard cap 改为完成并保存非空内容，自动 hard cap 仍拒绝半成品；shot/scene/camera/Seedance 的 restore、release 与按钮恢复统一进入嵌套 finally，workspace Blob/cleanup/save 任一抛错也只结算一次。
- 终审异常安全收口：acquire 前完成可前置快照/容器决策，`beginCaptureTransaction` 在 UI 异常时自回滚；workspace 周期 draw、同步 start 结算、start/timer 安装失败与迟到事件共用 exactly-once finalize；`recordBlob` 构造后 getter/setter/绑定失败会自清理，完整非空媒体不因 track/timer/UI cleanup warning 丢弃或谎报保存失败；浏览器与桌面 `dl` 在成功/失败下都 exactly-once revoke Blob URL。
